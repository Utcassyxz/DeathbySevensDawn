# 2026-11-08 交互与因果重构审计

本轮以用户八张截图为验收入口。旧版“通过298条检查”不代表新需求已满足，本轮另行验证。

## 根因
- NeighborSlice 同时管理物品、剧情、门、UI。世界物品已隐藏，但其交互范围和菜单未失效；拿取只改 Notice。
- Day2 foreshadow 跳过信息来源，凭空加入父亲，提前把准备物和敌意当成已知。
- FirstLoopPrologue 的旧 Day2 封门演出与新偷听争抢剧情入口。
- 邻居出口直接 LoadScene，绕过已有 RoomDoor2D 的落点契约。
- CityWorld 将场景 ID 直接呈现为同一栋楼的门，并把开发用每日攻略当作 HUD。
- NeighborCombat 用同一个 projectile 状态阻塞整个敌人更新，导致抓住玩家后敌人停止行动；玩家武器仅在命中后轻微移动。
- UI 大量双语硬编码，文案与逻辑分散，不能集中修改。

## 新的行为契约
1. 第二天醒来只提出出门走走；到401附近才听到第三夜毁楼密谋。随后敲门问询、受邀进入；强行开门是持有撬棍时的另一选择。
2. 物品：未查看 → 打开柜子（撬棍）→ 查看/主动记录 → 取走 → 世界交互耗尽。取走关闭模态，只显示短提示；背包仍可复查和记录。消耗不会刷新世界拾取。
3. 初访邻居是2D，帽子遮脑；玩家威胁引发摘帽与首次20SAN损失，再进入第一人称。获胜回原房间，离开回401门口。
4. 左键挥击有前摇、接触帧、收招；打空也演出，命中检查距离/朝向/墙体；受击僵直、碰撞约束击退。束缚与敌人行为独立，敌人继续逼近和近战。
5. 城市远方地点用西侧街路、东侧街路、上坡出口；不表现成同一栋楼的三扇相邻门。现场只呈现当前可用动词。
6. 玩家文本以 Resources/StoryText.json 为中文源，StoryTextEnglish.json 为英文源。原广告正文保持原样。编辑文字不改 ID、条件或存档字段。

## 实施与验证分阶段
- 已进入实施：流程因果、物品状态、门口落点、有效动词、武器/受击/束缚行为。
- 验证中：真实场景顺序，虚拟鼠标按下/释放，物品耗尽后重访，正常与死亡轮回回归。
- 视觉复核后再同步：现有 Unity 原工程与 GitHub feature/seven-day-city。
- 本次不把简单几何邻居模型宣称为完成角色美术；最终绑定模型与完整动画仍需要专门制作。
